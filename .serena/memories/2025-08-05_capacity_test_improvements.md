## 重要發現

### 1. 系統容量極限
- **40台機器人的不穩定性**：
  - 第1次運行：94.6% 完成率
  - 第2次運行：6.8% 完成率（嚴重死鎖）
  - 證明40台是系統的臨界點，容易發生災難性失敗

### 2. 最佳配置
- **25台機器人**：
  - 100% 完成率（極穩定）
  - 最低每訂單能耗（194.4）
  - 建議用於生產環境

### 3. 多Run測試的價值
- 成功捕捉到40台機器人配置的不穩定性
- 提供更可靠的性能數據
- 揭示了系統在臨界狀態下的脆弱性

## 技術細節

### 檔案隔離機制
```python
# 每個測試運行都有唯一ID
test_id = f"robots_{robot_count}_run{run_idx}_{uuid.uuid4().hex[:8]}"

# 環境變數隔離
env['SIMULATION_ID'] = test_id
env['NETLOGO_STATE_FILE'] = f'netlogo_{test_id}.state'
```

### 監控器架構
- 使用 threading 和 queue 實現非阻塞輸出收集
- 使用 rich.Live 實現實時UI更新
- 支援進程級別的監控和控制

## 使用建議

1. **測試配置**：
   - 短期測試：20-25台機器人
   - 長期穩定：25台機器人
   - 避免使用：40台或以上

2. **多Run測試**：
   - 關鍵配置建議運行3-5次
   - 使用串行執行確保隔離
   - 檢查結果的標準差判斷穩定性

3. **監控功能**：
   - 長時間測試使用背景執行
   - 定期檢查進度避免死鎖
   - 保存監控狀態用於事後分析
