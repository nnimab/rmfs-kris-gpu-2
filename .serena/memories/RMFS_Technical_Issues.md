# RMFS 專案技術問題與解決方案

## 核心技術問題

### 1. 獎勵系統複雜度
**問題**：
- `unified_reward_system.py` 有 591 行
- 混合 V3/V6/V7 三個版本的計算邏輯
- `calculate_step_reward_v7()` 單一方法超過 100 行

**建議解決方案**：
- 模組化重構，分離不同版本到獨立檔案
- 使用策略模式管理不同獎勵計算
- 目標簡化到 50-100 行核心邏輯

### 2. 訓練與評估不一致
**問題**：
- 訓練時使用的資料收集機制與評估時不同
- 導致訓練效果無法在評估中重現

**已修復部分**：
- `train.py` 加入 `update_system_metrics()` 調用
- `evaluate.py` 加入 signal_switch_count 收集

### 3. V7 系統問題
**DQN 死鎖問題**：
- 6 動作空間 + epsilon=1.0 導致完全隨機
- 路口 30 成為瓶頸（等待超過 655 ticks）

**機器人路徑 Bug**：
- 修復：`assignJobAndSetToTakePod()` 加入 `setMoveToTakePod()`

### 4. CSV I/O 效能
**已優化**：
- 批量寫入（`batch_processing`）
- 進程隔離（使用 `process_id`）

**可改進**：
- 考慮 HDF5 或 Parquet 格式
- 實作記憶體快取機制

## 模型訓練問題

### NERL 100% Keep 問題
**原因**：網路初始化全為 0
**修復**：
- 輸出層 uniform(-0.3, 0.3) 初始化
- 偏置遞增值確保動作差異
- 加入動作統計追蹤

### 模型相容性
**問題**：舊模型缺少 fc1 屬性
**修復**：加入 `load_state_dict` 向後相容處理

## 建議優先處理
1. 簡化獎勵系統（影響最大）
2. 統一資料收集介面
3. 建立模型版本管理系統
4. 考慮更高效的資料格式
